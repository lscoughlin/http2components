## Repairs and retained failure evidence

Initial Linux failures remain in the logs. They are not counted as passes.
The repairs include portable OpenSSL certificate generation, Linux static
library search paths, explicit TLS contexts in old probes, per-thread
SIGPIPE protection in test peers, and updated pool-key expectations.

The TLS client now checks for a pending authentication alert after a failed
transport write. The recovery has an absolute 100 ms limit, does not wait
for a busy reader lock, and does not enter the failed write path again.
Controlled transport tests cover these cases. The real TLS 1.3 rejection
matrix confirms the required client-authentication errors.

The Apache interoperation fixture needed readable document directories.
The HTTPS proxy fixture also trusted an old CA instead of the CA that signed
the generated client identity. The corrected full proxy matrix passes.

The SSE encoder previously copied its growing result for each appended
fragment. It now calculates the output size and fills one allocated buffer.
The unchanged hardening cases pass. Server shutdown also used the original
bind text as a numeric wake-up port. Linux tracing showed a connection to
port 127. The listener now records its actual bound port for shutdown.

The server test peers now distinguish unread data from EOF. They avoid
sending flow credit after the terminal WebSocket close. The HTTP/1 write
stall check uses queued-output progress, and the idle check uses the idle
timeout. A write timeout no longer substitutes for the keep-alive timeout.
The original slow-reader test still requires one waiting request to receive
HTTP 200; retries do not conceal an admission timeout.

The old mTLS tests expected session reuse. The TLS replacement contract
disables resumption. The revised tests first require a successful verified
full handshake. Both Linux versions issue no resumable session artifact.
The missing-client-certificate checks remain required and pass.

The last full server run before the final repairs executed 714 tests in
280.278 seconds, with one error and four failures. The later focused local
checks pass, but they do not replace a complete Linux rerun.

## Explicit peer limitations

The client interoperation A8 case needs a mid-flight GOAWAY trigger that the
tested nghttpd does not provide. The Autobahn expected-case configuration
retains its existing permessage-deflate exclusions for sections 12 and 13.
Neither exclusion was expanded during this run.

The Ubuntu Squid image uses GnuTLS. Its build cannot expose the configured
client-certificate subject log field or require and verify proxy client
certificates through the tested configuration. Those three rows are
explicitly unavailable. Apache runs the corresponding required identity
checks. The Squid omissions are not evidence that proxy mTLS enforcement
works on that image.
